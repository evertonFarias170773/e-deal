## 6. Evolução da Matriz de Permissões V2.1 e RPC Segura
**Decisão:** O sistema adotou a Matriz V2.1, migrando de verificações generalistas (ex. `isAdmin`) para permissões granulares organizadas por módulo. Para mitigar bloqueios de RLS e falsos positivos de sucesso no frontend, adotou-se a estratégia de gravar permissões via **RPC segura** em vez de UPDATE direto em `public.perfis`.
**Impacto:** Segurança ampliada contra auto-elevação de privilégios. A UI foi aprimorada (sticky button, ações em lote), mantendo a compatibilidade temporária com as roles V1 (Double Support). Os indicativos "(Legado V1)" foram retirados do front para uma apresentação mais limpa, mas o sistema preserva as chaves internamente até a remoção completa da Fase 4.

## 7. Infraestrutura Unificada de Escopo de Dados
**Decisão:** Em vez de helpers engessados por módulo (ex. `getEscopoPropostas`), adotou-se uma infraestrutura genérica de Escopo de Dados (`getDataScope`), que retorna os níveis padronizados: `own`, `team`, `company` ou `all`.
**Impacto:** A fundação já suporta a expansão orgânica de escopos. O módulo de Orçamentos é o primeiro piloto a utilizar escopo por vendedor (`own`).
